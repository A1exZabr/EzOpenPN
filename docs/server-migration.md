# Если доступ пропал: проверки и новый сервер

Не удаляйте сервер при первой ошибке. Недоступность сайта, неисправность профиля и блокировка IP являются разными ситуациями. Замена адреса помогает не всегда.

## Сначала проверьте простое

1. Выключите подключение в приложении. Работает ли обычный интернет? Если нет, сначала восстановите домашнее или мобильное соединение.
2. Включите профиль и попробуйте второй транспорт: A вместо B или B вместо A. Они независимы, но автоматическое переключение зависит от приложения; при необходимости выберите вручную.
3. Сравните Wi-Fi и мобильную сеть. Если на телефоне проверяете мобильную, отключите Wi-Fi, иначе это всё ещё будет прежний канал.
4. Проверьте в кабинете провайдера оплату, состояние VPS, лимит трафика, аварии и правила firewall. Для B особенно важен `443/udp`, для A нужен `443/tcp`.
5. Если SSH доступен, выполните на сервере:

```bash
sudo ezopenpn status
sudo ezopenpn doctor
```

Если есть ошибка сервиса, диска или сертификата, сначала исправьте её по [справочнику](troubleshooting.md). Проверьте, что профиль в панели активен, а приложение использует актуальную ссылку. Даже пять `healthy` не гарантируют прохождение трафика через сеть оператора.

Если SSH тоже не доступен, используйте аварийную консоль провайдера. Одновременная недоступность панели и SSH ещё не доказывает блокировку: сервер мог выключиться, поменять адрес или оказаться за закрытым firewall.

## Когда имеет смысл другой IP

Если сервер исправен, но его адрес недоступен только из конкретной сети, фильтрация IP является одной из возможных причин. Новый **другой** IP может помочь, если ограничение относится именно к старому адресу. Это рабочая гипотеза, а не обещание результата.

При блокировке диапазона адресов, сети дата-центра или самого способа подключения новый адрес у того же провайдера может ничего не изменить. При доступе только к разрешённым ресурсам или отключении интернета замена VPS также не гарантирует результат. Не покупайте много серверов подряд без проверки причины.

Перезагрузка или переустановка ОС обычно не означает смену IP. Перед заказом уточните у провайдера, выдаётся ли **новый публичный IPv4**, и сравните адреса. Создание нового VPS тоже не является гарантией нового адреса: выдачей управляет провайдер. Например, [DigitalOcean закрепляет IP за существующим сервером](https://docs.digitalocean.com/support/are-my-droplets-ip-addresses-static/); у вашего провайдера правила могут отличаться.

## Безопасный переезд

1. Не отменяйте старый сервер сразу. Сохраните необходимые данные и резервную копию на своём компьютере. Если сервер подозревается во взломе, не переносите его ключи и конфигурацию без проверки.
2. Создайте отдельный новый VPS с чистой поддерживаемой системой. Проверьте, что публичный IPv4 **отличается** от прежнего. При блокировке сети дата-центра сначала обсудите другой диапазон или площадку с провайдером.
3. Добавьте свой открытый SSH-ключ, проверьте вход и настройте [защиту SSH](ssh-security.md). Разрешите нужные порты.
4. Установите EzOpenPN [одной командой из инструкции](getting-started.md#4-установите-ezopenpn), придумайте новый пароль панели.
5. Создайте новые профили для каждого устройства. Импортируйте их в приложения, выберите новые записи. Адрес панели тоже будет новым.
6. Проверьте сайты и передачу данных через оба транспорта, отдельно из домашней и мобильной сети. Убедитесь, что выбрали именно новый профиль, а не старую запись.
7. Только когда новое подключение проверено и нужные данные сохранены, отмените старую услугу у провайдера. Удалите старые профили из приложений и обновите закладку панели.

Для новичка переезд означает **новую установку и новые ссылки**. Архив EzOpenPN содержит старый адрес, сертификаты и секреты; команда `restore` не является автоматической миграцией на новый IP. Не копируйте старый конфиг целиком и не заменяйте IP текстовым редактором. Не перепривязывайте к новому VPS старый заблокированный адрес.

## Как не продолжить платить за старый VPS

«Выключить», «переустановить» и «отменить аренду» могут быть разными действиями. Выключенный сервер нередко продолжает оплачиваться; например, это прямо указано в [условиях DigitalOcean](https://docs.digitalocean.com/products/droplets/details/pricing/). Точный порядок смотрите у своего провайдера.

Перед кнопкой Delete, Destroy или «Отменить услугу» ещё раз сверьте **старый** адрес и имя сервера. Удаление может безвозвратно уничтожить диск, включая копии, оставшиеся на нём. Затем проверьте статус отмены, дату прекращения списаний и отдельно оплачиваемые диски, снимки или дополнительные адреса. Сохраните подтверждение отмены.
