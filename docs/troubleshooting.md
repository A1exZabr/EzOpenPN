# Справочник диагностики

Начните с двух команд:

```bash
sudo ezopenpn status
sudo ezopenpn doctor
```

Не удаляйте файлы состояния и не переустанавливайте Docker наугад. Найдите код `E_...` в выводе и используйте безопасную проверку ниже.

## Доступ и общие аргументы

| Код | Что проверить |
|---|---|
| `E_INSTALL_UNAVAILABLE` | Убедитесь, что `/etc/ezopenpn/current` и `/usr/local/bin/ezopenpn` принадлежат этой установке. Для восстановления запустите `reinstall`. |
| `E_INSTALL_ARGUMENT` | Уберите неизвестные параметры или укажите оба лабораторных файла. |
| `E_INSTALL_STATE` | Не редактируйте `install.json`; восстановите проверенный архив или запустите `reinstall`. |
| `E_INSTALL_CHECKPOINT` | Повторите установку. Если код остался, сохраните `doctor` и не удаляйте checkpoint руками. |
| `E_INSTALL_PHASE`, `E_CHECKPOINT_VALUE` | Файл незавершённой операции повреждён. Не продолжайте изменяющие команды до восстановления из архива. |
| `E_OPERATION_LOCKED` | Дождитесь завершения другой команды. Проверьте процессы, но не удаляйте lock во время работы. |
| `E_OPERATION_NAME` | Используйте только опубликованные команды CLI. |
| `E_UNSAFE_PATH`, `E_LAYOUT_PATH`, `E_RELEASE_PATH` | Не подменяйте системные пути и symlink. Запустите `doctor`, затем `reinstall`. |

## Предварительная проверка

| Код | Что проверить |
|---|---|
| `E_PREFLIGHT_ROOT` | Войдите как root или используйте рабочий `sudo`. |
| `E_PREFLIGHT_TTY` | Запускайте установку из интерактивной SSH сессии, а не из панели без TTY. |
| `E_PREFLIGHT_ARCH` | Нужна архитектура amd64 или x86_64. |
| `E_PREFLIGHT_OS` | Нужна одна из четырёх систем из [таблицы совместимости](compatibility.md). |
| `E_PREFLIGHT_SYSTEMD` | Используйте обычную серверную систему с systemd, не системный контейнер. |
| `E_PREFLIGHT_PUBLIC_IP` | Адрес должен быть публичным IPv4 и присутствовать на интерфейсе сервера. |
| `E_PREFLIGHT_RESOURCES` | Освободите диск или выберите сервер с 1 ГиБ памяти и 4 ГиБ свободного места. |
| `E_PREFLIGHT_TIME` | Проверьте дату и часовой пояс сервера. Включите синхронизацию времени, если часы отличаются больше чем на 5 минут. |
| `E_PREFLIGHT_PORT` | Команда показывает владельца занятого порта. Остановите только известный вам сервис или выберите чистый VPS. |
| `E_PREFLIGHT_CONTAINERS` | На сервере найдены чужие работающие контейнеры. Используйте отдельный чистый VPS. |
| `E_PREFLIGHT_FIREWALL` | Обнаружена ручная ограничивающая политика. Разберите её отдельно, не отключайте вслепую. |
| `E_PREFLIGHT_NETWORK` | Проверьте DNS, исходящий HTTPS, время и доступ к GitHub, Docker registry и ACME. |
| `E_PREFLIGHT_INTERRUPTED` | Повторите ту операцию, которая была прервана, чтобы сработало восстановление журнала. |

## Логин и пароль администратора

| Код | Что проверить |
|---|---|
| `E_CREDENTIAL_TTY` | Откройте интерактивную SSH сессию. |
| `E_CREDENTIAL_INPUT` | Повторите ввод и не закрывайте stdin терминала. |
| `E_CREDENTIAL_LOGIN` | Логин должен содержать от 1 до 64 символов. |
| `E_CREDENTIAL_LENGTH` | Пароль должен содержать от 12 до 1024 символов. |
| `E_CREDENTIAL_CONFIRM` | Два введённых пароля должны совпасть. |
| `E_CREDENTIAL_REUSE` | Пароль не должен полностью совпадать с логином. |
| `E_CREDENTIAL_COMMAND` | Используйте штатную команду установки или сброса. |
| `E_ADMIN_STATE` | База администратора недоступна или имеет неожиданное состояние. Сначала сделайте backup, затем запустите `doctor`. |
| `E_ADMIN_RESET` | Сброс не завершился. Проверьте `control` через `status` и повторите после исправления. |

## Docker, firewall и конфигурация

| Код | Что проверить |
|---|---|
| `E_DOCKER_OS` | Репозиторий Docker не соответствует поддерживаемой системе. Не добавляйте случайный репозиторий вручную. |
| `E_DOCKER_KEY` | Проверьте системное время, DNS и HTTPS к официальному репозиторию Docker. |
| `E_DOCKER_HEALTH` | Проверьте `systemctl status docker` и свободный диск. |
| `E_FIREWALL_BACKEND` | Поддерживаются неактивный firewall, UFW и firewalld. |
| `E_FIREWALL_CONFLICT` | Имя управляемого firewalld service уже занято чужим файлом. Не перезаписывайте его. |
| `E_RENDER_SOURCE`, `E_RENDER_CONFIG` | Release-шаблон отсутствует или итоговая конфигурация не прошла проверку. Запустите `reinstall`. |
| `E_IMAGE_REFERENCE` | Image lock не содержит полного digest. Повторно скачайте проверенный release. |
| `E_SECRET_FILE` | Секретный файл отсутствует, является symlink или имеет неверный размер. Восстановите backup. |
| `E_RUNTIME_KEY`, `E_RUNTIME_MATERIAL` | Runtime значения повреждены. Не генерируйте их отдельно, используйте `reinstall` или restore. |
| `E_TARGET_LIST`, `E_TARGET_UNAVAILABLE` | Автопроверка не нашла подходящий TLS 1.3 target. Проверьте исходящую сеть и повторите позже. |
| `E_LAB_CERTIFICATE`, `E_LAB_CONFIRMATION` | Смотрите закрытый расширенный раздел ниже. |

## Запуск и сертификат

| Код | Что проверить |
|---|---|
| `E_HEALTH_TIMEOUT` | Один из сервисов не стал healthy. Выполните `status`, затем запросите отфильтрованные логи этого сервиса. |
| `E_CERTIFICATE_TIMEOUT` | Проверьте публичный IPv4, входящий `80/tcp`, время и отсутствие внешнего прокси. |
| `E_RELEASE_VERIFY` | Подпись, checksum, manifest или workflow identity не совпали. Ничего не запускайте из этого набора. |
| `E_REINSTALL_VERSION` | Текущая версия не определена. Восстановите `install.json` из backup. |

## Логи

| Код | Что проверить |
|---|---|
| `E_LOG_SERVICE` | Укажите один из пяти допустимых сервисов. |
| `E_LOG_ARGUMENT` | `--since` и `--tail` принимают только ограниченные положительные числа. |
| `E_LOG_SANITIZER` | Фильтр отсутствует или заменён. Не показывайте сырые логи, сначала выполните `reinstall`. |

## Резервная копия и восстановление

| Код | Что проверить |
|---|---|
| `E_BACKUP_TOOL`, `E_BACKUP_LAYOUT` | Модуль или фиксированные каталоги отсутствуют. Запустите `reinstall` до новой копии. |
| `E_BACKUP_DATABASE`, `E_BACKUP_SNAPSHOT` | SQLite не создала проверяемый online snapshot. Проверьте диск и `doctor`. |
| `E_BACKUP_STAGE`, `E_BACKUP_NAME`, `E_BACKUP_ARCHIVE` | Каталог небезопасен, имя занято или архив не прошёл повторную проверку. Не используйте этот файл. |
| `E_RESTORE_VERIFY`, `E_RESTORE_STAGE` | Архив, checksum, manifest, пути или схема не прошли проверку. Сервисы ещё не должны быть заменены. |
| `E_RESTORE_PREIMAGE` | Не удалось сохранить текущее состояние перед restore. Освободите диск и остановитесь. |
| `E_RESTORE_HEALTH` | Восстановленное состояние не прошло healthcheck, начат возврат. |
| `E_RESTORE_ROLLBACK` | Автоматический возврат завершился не полностью. Не запускайте purge; сохраните оба архива и журналы. |

## Обновление и переустановка

| Код | Что проверить |
|---|---|
| `E_UPGRADE_VERSION`, `E_UPGRADE_CURRENT` | Версия release или текущая установка не прошла строгую проверку. |
| `E_UPGRADE_DOWNGRADE` | Выбранная версия ниже установленной. Обычное понижение запрещено. |
| `E_UPGRADE_RELEASE`, `E_UPGRADE_PREPARE`, `E_UPGRADE_STAGE` | Новый release не скачан, не проверен или не подготовлен. Текущая версия должна остаться активной. |
| `E_UPGRADE_BACKUP` | Проверенный backup перед переключением не создан. Освободите диск и повторите. |
| `E_UPGRADE_PREFLIGHT` | Среда больше не проходит maintenance preflight. Исправьте указанный конфликт. |
| `E_UPGRADE_HEALTH` | Новая версия не стала healthy, запускается автоматический возврат. |
| `E_UPGRADE_ROLLBACK` | Возврат прежней версии завершился не полностью. Остановите изменения и сохраните диагностический bundle. |
| `E_UPGRADE_JOURNAL`, `E_UPGRADE_CHECKPOINT` | Журнал повреждён или принадлежит другой операции. Не удаляйте его руками. |
| `E_UPGRADE_RECOVERY` | Автовосстановление прерванной транзакции не завершилось. Требуется разбор журналов без секретов. |

## Остановка и удаление

| Код | Что проверить |
|---|---|
| `E_REMOVE_INTERRUPTED` | Сначала завершите восстановление через `update` или `reinstall`. |
| `E_UNINSTALL_SERVICES` | Не все управляемые компоненты остановились. Проверьте Docker и systemd, данные сохранены. |
| `E_PURGE_TTY` | Полное удаление разрешено только из интерактивного терминала. |
| `E_PURGE_BACKUP` | Финальный проверенный архив не создан. Ничего не удалено. |
| `E_PURGE_CONFIRMATION` | Одно из двух точных подтверждений не совпало. Данные сохранены. |
| `E_PURGE_SERVICES` | Компоненты не остановились, поэтому удаление данных отменено. |
| `E_PURGE_REMOVE` | Удаление фиксированных путей завершилось частично. Финальный архив остаётся вне удаляемого каталога. |

## Расширенный лабораторный сертификат

Этот режим не предназначен для обычной установки и не даёт стандартной браузерной проверки доверия. Он доступен только если `install.sh` сначала скачан в файл, а сертификат и ключ созданы вами для того же публичного IPv4.

```bash
sudo bash ./install.sh \
  --advanced-lab-certificate /absolute/path/server.crt \
  --advanced-lab-key /absolute/path/server.key
```

Нужно передать оба абсолютных пути. Файлы не могут быть symlink, public key должен совпадать, а сертификат обязан содержать IP SAN обнаруженного адреса. Затем терминал отдельно попросит ввести `LAB`. Не используйте `-k` как постоянное решение в браузере или клиенте.
