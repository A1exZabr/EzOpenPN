# Восстановление и обслуживание

Все команды выполняются на сервере по SSH. Они используют одну блокировку, поэтому две изменяющие операции одновременно не запускаются.

Для `root`, если команда `sudo` отсутствует, уберите её из примеров. Потерянный SSH-ключ восстанавливается через кабинет провайдера по [инструкции безопасности](ssh-security.md), а не через сброс пароля панели.

## Быстрая проверка

```bash
sudo ezopenpn status
sudo ezopenpn doctor
```

`status` показывает версию, адрес панели, состояние пяти сервисов, сертификат и число активных профилей. `doctor` повторно проверяет окружение, права файлов, Compose, базу, сертификат, согласованность транспортов и публичный HTTPS.

Безопасный фрагмент логов конкретного сервиса:

```bash
sudo ezopenpn logs control --since 3600 --tail 200
```

Допустимые имена: `control`, `xray`, `hysteria`, `gateway`, `cert-sync`. Перед показом значения проходят фильтр известных секретов и ссылок.

## Сброс доступа к панели

```bash
sudo ezopenpn admin reset-password
```

Введите новый пароль дважды. Команда меняет хеш администратора и отзывает открытые сеансы панели. Профили, ссылки и серверные ключи сохраняются.

## Резервная копия

```bash
sudo ezopenpn backup
```

Команда создаёт проверенный архив в `/var/backups/ezopenpn`. В архив входят база, мастер-ключ, конфигурация, серверные секреты, сертификаты и runtime-файлы. Архив даёт полный доступ к экземпляру, поэтому храните его как пароль и не загружайте в публичные хранилища.

Копия на самом сервере не переживёт удаление его диска. Чтобы забрать архив, скопируйте точный путь, который напечатала команда. Затем **на своём компьютере**, в отдельном терминале, выполните (замените `SERVER_IP` и `ARCHIVE.tar.gz`):

```bash
scp -i ~/.ssh/ezopenpn_ed25519 root@SERVER_IP:/var/backups/ezopenpn/ARCHIVE.tar.gz .
scp -i ~/.ssh/ezopenpn_ed25519 root@SERVER_IP:/var/backups/ezopenpn/ARCHIVE.tar.gz.sha256 .
```

В PowerShell путь ключа пишется `"$env:USERPROFILE/.ssh/ezopenpn_ed25519"`. Точка в конце означает текущую папку компьютера. При нестандартном SSH-порте у `scp` используется заглавная `-P`. **Нужны оба файла**: архив и одноимённый `.sha256`. Команда backup печатает только путь архива, но файл контрольной суммы создаётся рядом обязательно. Если входите не как root и не имеете права прочесть архив, не открывайте его всему миру через `chmod 644`: используйте безопасное копирование с административными правами.

Храните скачанные файлы в зашифрованном хранилище, не в общей папке. Для восстановления на **другой IP** используйте [план переезда](server-migration.md): обычный restore не переписывает старый адрес автоматически.

Для восстановления верните **оба файла** на сервер в один каталог с исходными именами. Например, со своего компьютера:

```bash
scp -i ~/.ssh/ezopenpn_ed25519 ARCHIVE.tar.gz ARCHIVE.tar.gz.sha256 root@SERVER_IP:/var/backups/ezopenpn/
```

Не перезаписывайте другую копию с тем же именем без проверки. Затем на сервере задайте обязательные права для этой конкретной пары файлов:

```bash
sudo chown root:root /var/backups/ezopenpn/ARCHIVE.tar.gz /var/backups/ezopenpn/ARCHIVE.tar.gz.sha256
sudo chmod 600 /var/backups/ezopenpn/ARCHIVE.tar.gz /var/backups/ezopenpn/ARCHIVE.tar.gz.sha256
```

Восстановление на том же адресе:

```bash
sudo ezopenpn restore /var/backups/ezopenpn/ARCHIVE.tar.gz
```

Сначала проверяются checksum, manifest, пути, база и совместимость версии. Затем создаётся снимок текущего состояния. Если восстановленный экземпляр не проходит healthcheck, прежнее состояние возвращается автоматически.

## Обновление

```bash
sudo ezopenpn update
```

Обновление принимает только подписанный стабильный выпуск, запрещает случайное понижение версии, делает резервную копию и переключается после полной проверки. При ошибке возвращаются прежние release-файлы, база и закреплённые образы.

Для предварительного v0.1.9 стабильный канал пока может содержать более старую версию. В этом случае `E_UPGRADE_DOWNGRADE` является защитным отказом; v0.1.9 сохраняется. Не пытайтесь обойти его и не используйте команду чистой установки как способ выбора версии на существующем сервере.

## Переустановка без потери данных

```bash
sudo ezopenpn reinstall
```

Используйте её, если файлы текущего выпуска повреждены или контейнеры нужно пересоздать. Мастер-ключ, профильные строки, ссылки, логин администратора и публичный адрес должны сохраниться.

## Остановка с возможностью вернуть всё

```bash
sudo ezopenpn uninstall
```

Команда отключает unit, удаляет только управляемые контейнеры и правила firewall, но оставляет конфигурацию, базу, секреты, резервные копии и release-файлы. Для возврата выполните команду установки из [начала работы](getting-started.md#4-установите-ezopenpn): она возобновит сохранённый стек, правила firewall и автозапуск. В предварительном v0.1.9 после этого возможен `E_UPGRADE_DOWNGRADE`, если стабильный канал старше: проверьте `status` и `doctor`, прежняя версия должна быть запущена. Одна команда `reinstall` не восстанавливает удалённые uninstall правила firewall и автозапуск. Не путайте uninstall с отменой оплаты VPS у провайдера.

## Полное удаление

```bash
sudo ezopenpn purge
```

Перед удалением создаётся и проверяется финальный архив вне удаляемого каталога. Затем терминал требует точно ввести имя продукта и отдельное слово `DELETE`. Удаляются только три фиксированных корня, CLI и systemd unit. Путь сохранённого финального архива печатается в конце.

## Прерванная операция

Не удаляйте `current.json` или `upgrade-transaction.json` руками. Повторите ту же команду `update` или `reinstall`: журнал восстановит предыдущую или завершит текущую транзакцию. Если код повторяется, сохраните вывод `status`, `doctor` и отфильтрованные логи, затем сверяйтесь со [справочником](troubleshooting.md).
