# Участие в разработке

Спасибо за желание улучшить EzOpenPN. Проект принимает небольшие, проверяемые изменения с нейтральной терминологией и без пользовательских данных.

## Перед изменением

1. Создайте отдельную ветку от актуального `main`.
2. Не добавляйте сгенерированные ключи, ссылки, адреса рабочих серверов, логины, базы, архивы или сырые логи.
3. Сначала добавьте тест, который воспроизводит проблему или фиксирует новый контракт.
4. Для изменений транспорта заранее опишите измеряемую внешнюю проверку. Handshake без передачи данных не считается доказательством.

## Локальная проверка

```bash
uv run python tools/content_guard.py .
make check
bash tools/generate_xray_proto.sh --check
bash tools/lock_images.sh --check
```

Для shell-кода дополнительно запустите Bats и ShellCheck. Для Compose изменений нужны policy и integration тесты. Для публичного текста проверьте относительные ссылки и отсутствие запрещённой типографики.

`tools/content_guard.py` обязателен для любого изменения. Он блокирует исторические обозначения, старые идентификаторы, возможные секреты и два запрещённых Unicode-разделителя.

## Pull request

В описании укажите:

- что изменилось и зачем;
- какие команды проверки выполнены;
- какие проверки требуют Linux, Docker, VM или внешней сети;
- затрагиваются ли миграции, persistent data или release assets;
- почему вывод и fixtures не содержат секрет.

Не отмечайте непроведённую проверку как успешную. Не добавляйте реальные network evidence вручную без валидатора и предварительного просмотра sanitization.
